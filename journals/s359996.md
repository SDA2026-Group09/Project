# Journal

## 2026-04-30

We met as a group earlier this month to choose the open source project to analyze. After looking at a few options we picked Processing (github.com/processing/processing4) because it is mostly Java, has clear modules (core, app, java), and is still under active development. After that we divided the three reports: design and architecture were split between two members each, and I took the overview alone since it is the shortest and the other two reports somewhat depend on it.

In the days after I cloned the repo and read the README and BUILD.md to get a first idea of what the system actually does. The structure has three top-level modules (core, app, and the java mode) and uses Gradle for building, with Ant still around for installer packaging. I also noted that the core library is LGPL while the rest is GPL, which I think is worth mentioning in the report because it explains why the engine is structured to be embeddable on its own.

## 2026-05-14

This week I focused on building up the content for the overview. I went through the project guidelines once more to confirm the structure: a 1000 word limit excluding diagrams, with sections on purpose, stakeholders, system description, and code statistics. I started drafting the first two sections and listed the main stakeholders (educators, artists, the Processing Foundation, library authors, and downstream applications that embed the core library).

I also spent some time looking at the module dependencies inside Processing to understand how to describe the system clearly. The core module has no dependencies on the rest, app depends on core, and the java mode depends on both. The PDE is also designed to be language-agnostic, with Java being one possible "mode" plug-in. This layering is the key thing I want to communicate in the overview.

## 2026-05-24

I finished the first complete draft of the overview today. It has three sections (Purpose and Stakeholders, System Description, and Code Statistics) and includes a Mermaid diagram showing the pipeline from a `.pde` sketch through preprocessing, compilation, and execution in a separate JVM. I used cloc to get the line-of-code numbers and the GitHub API for contributor and activity stats.

The current word count is 929 (measured with the bash command the professor specified), under the 1000 cap. The draft is on the `overview` branch. Next step is to share it with the team for review and adjust if anything overlaps with what the design or architecture reports cover.

Now that the overview is in a good shape, I would also like to help out with the design or architecture parts if there is anything left to do there. I will check with the team in the next meeting.
